## 实际会话

真实的 `codex exec --ephemeral` 运行在独立挂载和网络命名空间。安装缓存和已审阅的配置只读挂载。通过观察测试进程定位到插件策略查找路径，将样例策略只读挂在该私有路径。模型端由回环地址上的固定响应产生，依次提交两个原生 `apply_patch` 请求、一个 `exec_command` 请求（`true`）和结束回合的文本。钩子调度、补丁执行、沙箱和 Stop 续跑均由 Codex 完成。

原生权限配置继承 `:read-only`，只开放样例 `output/` 目录。两份补丁的目标都在这个可写目录里，唯一区别是钩子清单只包含第一个文件。样例任务预先处于 `running`。每次独立试验结束后由外层进程读回结果。

| 核对项 | 实测结果 |
| --- | --- |
| SessionStart | 第一次模型输入收到“HuTools 调用检查已加载，批次 B02-INDEPENDENT-HOST”。 |
| 清单内补丁 | 宿主报告 `file_change` 开始并完成。外部读回 `output/allowed.txt` 内容为 `B02\n`（以换行结尾）。 |
| 同目录清单外补丁 | 宿主报告 `Command blocked by PreToolUse hook`，理由为“补丁目标不在精确批准清单：output/unlisted.txt”。外部检查该文件不存在。 |
| 禁止 shell | 工具回执包含“工具调用未获精确批准：Bash”。正常策略的 `approved_calls` 为空。 |
| 任务仍在运行 | 第一次收尾后，下一次模型输入收到“任务仍在执行”反馈。随后触发第二次结束，CLI 正常退出。完整试验共 5 次模型请求。另行直接运行安装件确认已完成且证据齐全的样例返回空对象。 |
| 保护检查 | 在相同样例权限配置下，以只写、不截断方式打开实际挂载的策略文件、已安装的 `guard.py` 和样例任务状态，三项均返回 `EROFS`。 |
| 过期策略 | 单独会话对同一条清单内补丁返回 `Command blocked by PreToolUse hook`，理由为“策略已到期或缺少时区”。两个文件均不存在，策略字节与试验前一致。 |
| 策略字段错误 | 单独会话将 `write_paths` 设为字符串，宿主拒绝同一条补丁，理由为“write_paths 必须是路径列表”。两个文件均不存在，策略字节与试验前一致。 |

两个反例在收到补丁结果后由测试端结束会话，子进程的 `-15` 对应测试结束信号。验收依据为宿主明确拒绝的原因和文件结果。正常会话的只读环境还产生了系统技能目录刷新失败的日志，独立核对的 HuTools 事件与文件结果如表所示。

## 适用范围

本项通过本机 CLI 的一次性绑定验收。正式开发工作区仍未绑定策略。原生沙箱的精确写入对照通过于正式工作区的一次性子目录，系统临时目录的正向写入失败。最初未声明补丁能力的模拟模型收到“unsupported custom tool call”，随后改用宿主已有的模型工具目录；未指定可写范围时获准补丁也未落盘，最终运行显式选择已实测的目录级配置。

持续 shell 和后续输入、任意子进程、MCP、嵌套执行入口、处理器缺失或超时、其他宿主和机器不在此次通过范围内。高风险操作需针对实际工程另行绑定并实测相应入口。资料卡片已在正式会话收到并回传用户答复；仅输入“运行”的菜单保留独立的现场复核项。
