# 开发需求与方案

本预览版推进到可实施的设计和验收计划。用户要求直接修代码时，说明当前能交付的方案，并留下后续实施入口。

先查相关工程和既有能力，再用 [grill-with-docs](../../grill-with-docs/SKILL.md)讨论目标、使用场景、非目标和成功实例。只有当前决策所需事实不清时补问；行业方案用 [research](../../research/SKILL.md) 定向调查。

设计先看系统职责、状态所有者、接口与依赖、真实构建部署组合。必要时读 [codebase-design](../../codebase-design/SKILL.md)。旧约定不合理时给影响和升级建议，让用户决定。

将需求变成可验收实例与必要反例，按可交付功能切分，注明依赖和验收。参考 [tdd](../../tdd/SKILL.md)制定红—绿—重构与例外策略。测试覆盖实际需求，不要求每层全测或无限优化观察项。

复用现有设计/任务入口，写清修改前行为、原因、拟改文件/接口、修改后行为、验证与恢复。用户确认的具体范围记入原记录。需要审查方案/既有改动时读 [code-review](../../code-review/SKILL.md)。

报告开发完成状态时明确：需求/方案已确认、实现待实施。现场信息先查旧代码和文件，只让用户采集缺失的关键部分；指引写清目标机器、目录/环境、完整命令、输出、成功标志和最小失败反馈。
