# 交互和接入

## 菜单前只做必要识别

读取适用指令及短入口，识别根和明确待续任务，定向查工程约定的本机绑定（例如根目录的 `.env.hutools-materials`）。文件只作为数据读取。若读取受限，题干说明路径尚未核实，仍按[启动选项卡](../SKILL.md#尽早接住任务)询问。已有目标不重复模式选择。

明确的普通咨询可直接回答。每次用户重新启动工程工作流，读取本工程约定的本机绑定，在可用的选项卡中显示候选绝对路径，让用户选择沿用或更正。无候选时可填写位置或选待建立。可与整理选择、模式或目标同轮询问。仅同一次启动内的明确答复可复用；以后重新运行时仍须询问，换机或位置变化也重新确认。确认只表明本次资料库位置。等待答复时可继续处理无关事项。

## 目标明确后补查

- 咨询只查问题相关材料，足够即答，不建空任务。
- 分析核对所属项目、源码/材料身份和报告入口，不把承载工程当故障所属工程。
- 开发前核对根、Git 分支/基线、相关已提交/暂存/工作树/未跟踪差异及恢复；先摘要和限定路径，异常再展开。核对工程约定的待整合区和隔离标记，不把暂存输入自动纳入活动构建。
- 核对本批源码/构建/测试/运行入口、工具/副作用、保护范围及部署组合。环境缺失只阻塞对应验证，不借其他工程同名产物冒充。
- 当场显示工程名称、资料范围、本机库实际路径和确认状态。同次接手已确认时明确显示“本次已确认”；换机、换址或不可访问时说明受影响部分，请用户确认正确绑定。更换机器或同址更换库卷时在完整 `begin` 调用中使用 `--rebind-library` 并复核库范围。资料库待建时记录用户决定与适用范围。
- 用户新启动一次工程任务时询问本次是否整理文档和数据。将整理选择与资料库绑定分开记录；先前运行选择整理不代表下次也选择整理。同一次工作的连续回复不必反复询问。明确跳过或仅回答了路径时，不开始盘点、建目录或修改整理标记；尚未回答整理选择时保留问题。选择整理后核对[持久整理记录](materials.md#运行时从哪里开始)。首次盘点工程和绑定库中属于本项目的全部约定范围；以后依据记录接续或按任务更新。纯咨询沿用上文的直接回答路径。

## 唯一工程规则文件

工程首次接入时以根 AGENTS.md 为唯一活动规则入口，不要求独立工程契约或模板。普通问答不暗中初始化。经理先从 README、活动设计/决定、现有治理文件、构建配置及用户指示提取适用规则；注明出处、版本、适用范围，区分工程事实和用户授权。历史授权不自动续期，模板占位、源码现状和原始日志不作为用户决定。

从共同规则逐类裁剪：源码/用户改动保护、修改前确认、接口与部署兼容、构建验证、证据与恢复、外部资料边界。证据明确则采纳；不适用则跳过；无历史依据、冲突或重大变化只问影响工作的关键问题，用卡片收集可选决定，未答不推定。人和工具共用同一份规则；不把主机私有路径、敏感数据或未经授权的决定发布到 Git。

将已核定条目写入任务临时 JSON 数组，每项为 rule 加 source（工程根相对的现存证据文件）或 confirmation（明确答复的日期与范围）。输入仅用于生成，不是第二份规则或授权。运行包内 [project_rules.py](../../../tools/project_rules.py) 的 `--root 工程绝对路径 --decisions 条目文件` 先看预览，核对无遗漏与冲突；首次落盘加 `--init`。工具不扫描用户主目录，也不判断证据语义。相同内容不改目标；不同内容、链接或无法核实的出处拒绝自动覆盖。已有人工规则时按差异提案更新，保留用户修改；常规再次接手以现有规则为准，有变化才更新。

新工程没有规则文档时，经理在工程接入中核对已有决定，缺口按上节用选项卡确认。在用户已同意为该工程生成规则的范围内，经理直接调用 `--init` 创建根 AGENTS.md 并核对结果。普通咨询、纯预览和待确认的决定沿用各自边界。

已有工程需要合并规则时，先阅读工程入口和候选正文，查找实际引用、加载方式及适用范围。判断哪些有效决定属于根规则，哪些属于下级独立约定，哪些文件兼作说明、工具输入、仍在使用的模板或历史证据。任何文件名、后缀和候选数量都不能决定退役；无法判断、存在冲突或缺少迁入依据时保留待确认。

经理按本次审阅结果在工程外准备临时 JSON 数组，每个实际文件一项，根 AGENTS.md 由工具单列。示例项为 `{"path":"docs/交接手册","role":"mixed","scope":"root","action":"update","reason":"保留操作说明，更新规则入口","rules":[1],"consumers":[]}`。path 和 consumers 均为工程根相对路径；role 可取 rules、template、mixed、document、unknown，scope 可取 root、nested，action 可取 keep、update、retire、pending。rules 列出已核定条目的序号，从 1 开始；无适用条目用空数组。逐项核对消费者后填写 consumers；拟退役文件的活动引用须登记相应更新。为迁入规则选择切换后仍可读取的出处，或采用真实的用户确认。

用 `--root 工程绝对路径 --decisions 条目文件 --migration-preview 审阅清单` 生成只读预览。结合 decisions 与 files 显示根文件差异、各文件的理由、对应条目、活动引用及未决项。现有人工条款逐项复核；遗漏或有冲突先回到选项卡。没有旧规则可退役也可正常生成预览。清单校验依赖经理真实读取内容，不能据此声称工具自动发现了全部引用。

用户要求正式切换时，经理负责准备并执行本批操作：

1. 阅读每个 update 文件的现有内容，保留人工修改，只调整实际需要迁移的引用。将这些文件的完整新正文保存为临时 JSON 对象，键为工程根相对路径。需要切换本机绑定时，可额外包含 `.env.hutools-materials` 的已确认单行正文。已登记的活动消费者如仍提及拟退役文件，复核并解决引用后再准备。
2. 在原预览命令上增加 `--changes 正文.json --prepare 工程外的新私有批次目录`。没有导航或绑定改动可省略 changes。选择用户可恢复、父目录已存在的本机位置。准备返回本批 SHA256、每个文件的完整差异和逐项理由；目录中的 plan.json 保存实际原内容、原权限、新正文、来源指纹和工程身份，私有保留至切换及接手验收完成。不要把本机绑定内容发布到 Git。
3. 向用户展示本工程的路径、具体差异、退役项和恢复位置。对可选决定用选项卡询问“应用这份清单”或“返回修改”，把实际答复对应到展示时的批次和 SHA256。生成摘要、模型自报、沉默或先前批准均不能代替这次答复。若宿主允许执行这个调用，收到确认即由经理在同一任务调用 `project_rules.py --root 工程绝对路径 --apply 批次目录 --confirm 已展示批次的SHA256`，无需用户再敲命令。摘要用于校验内容，执行权限沿用宿主。绑定过期、宿主拒绝或仅获准只读时如实报告，不改策略或改走其他写入入口。
4. 工具核对原件及来源，先原子写入各新文件并逐一校验，再仅退役清单指定的文件。迁移期间由同一写入者维护目标，工具会串行化同工程的迁移。进程中断且无漂移时，以原确认及同一批次接续；发现用户新改动、内容或恢复文件不符时，保留现场并重新审阅。收到 complete 后核对活动入口和必要的新会话接手。需恢复时从私有 plan.json 的 files 条目提取 before 及 mode，先与 after 核对现状；原先不存在的文件以空值标记。保留用户后续修改，只在明确的恢复范围内操作。

## 提问与接续

优先可用卡片，每轮通常 1～3 个问题，选项短且互斥，推荐附理由；缺卡片用文字，不虚构工具。附件和密码走正规入口。取消/预选/超时不算批准；必要问题未答保留等待，依赖动作不执行。

答复到达即续，只重开受影响步骤。中断后从[任务记录](../assets/task.md)核对批准范围、源码/规则版本、未完成副作用、旧 worker/进程与证据；确认旧写入者状态前不重派同一资源。变化导致旧证据失效则保留历史重验。用[接入字段](../assets/project-context.md)裁剪，不强制复制模板。
