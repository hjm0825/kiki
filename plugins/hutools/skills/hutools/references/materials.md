# 资料生命周期与恢复

资料库确认沿[接入](intake.md)，处置授权沿[共同规则](rules.md)。不要求数据库服务或固定目录，机器绑定与材料身份分开；源日志追加保存，摘要不复制原始流。

## 让读者找到当前有效的文档

任务与资料范围明确后，资料管理员沿工程首页、任务目录和已确认的资料库索引，对照目录中与本任务有关的实际文件。范围内主动找出未挂接的方案、失效链接、指向旧版的“当前”入口和重复索引。首次生成文档时同步挂接，方案变化和阶段收尾时复查。明确要求整理整库时覆盖约定的全库范围；普通任务限定在相关目录。单人执行时由经理兼任。

按读者要解决的问题组织已有导航，例如“了解方案”“安装使用”“查看实施和证据”。读标题与内容、版本及已有决定再确定归属；把用户方案放在任务首选入口，技术资料在需要时可继续追溯。复用已有栏目，在文档之间标明可证实的替代关系。能在授权范围内核实的分类、链接、阅读顺序直接修好，并从首页实际走到当前文件；仅有线索时标明待核，不凭日期判定作废。

批量改名、移动、合并或删除已有文件，先给出精确范围、引用影响与恢复方式，按已有授权处理。日常整理优先维护阅读入口，让历史版本和原始依据保有出处。

## 资料保留与恢复

| 类别 | 保留与退出依据 |
| --- | --- |
| 核心资产：源码、有效配置、必要输入和恢复说明 | 随受支持版本保留，迁移携带真实依赖 |
| 关键证据：报告及必要失败/复现材料 | 摘要长期保留；原始材料保留最小完整集合，未决失败/争议不因后来通过而删除 |
| 可重建数据：构建/缓存等 | 实际重建方法可用、无唯一修改/活动占用/恢复依赖才列候选 |
| 过程资料：临时记录/备份等 | 收尾核替代结果和恢复点，必要部分转关键证据，其余按批准条件审查 |
| 来源/唯一性未知 | 原位保护，不猜测可删除 |

首次生成/使用时登记所属任务/项目/批次、输入版本及差异、路径基准、状态、保留理由/退出条件、迁移范围和复查点。任务/问题报告复用为索引，大型原始资料只引用；外部项目不混入承载工程验收，忽略文件不等于可删除。

归档/处置前列精确文件清单、真实路径/符号链接、类别/大小、保留条件、活动与其他受支持工作区依赖、唯一性、恢复和不可恢复损失。持续授权须具体到目录、类别、条件和动作，未覆盖项另确认。到期只复查；源变化、目标冲突、身份/校验不符或唯一性未知时保留并停止相关动作。

归档先复制到唯一批次，核对内容/身份、可读性和索引；归档不自动授权删除原件。获准移除时再次核对源未变化，记录实际目标和结果；失败保留原件与中间状态。迁移记旧标识到新位置，不批改原始证据内部历史路径。清单工具不替代来源/唯一性人工判断。

收尾沿工程入口→任务→证据/绑定检查新增/修改/忽略产物、恢复材料及保留边界；修导航不等于原件完整。需要场景复现时沿消费者真实加载格式保存和实测，不制造占位格式冒充可用。

需要精确清单及可恢复归档/隔离时读[资料工具说明](../../../tools/lifecycle.md)，再使用[包内工具](../../../tools/lifecycle.py)。其 cleanup 只列候选、quarantine 是可恢复移动，不是永久删除；工具不自动判断跨工作区依赖或用户批准真伪。
