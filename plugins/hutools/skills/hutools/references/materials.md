# 资料生命周期与恢复

资料库确认沿[接入](intake.md)，处置授权沿[共同规则](rules.md)。不要求数据库服务或固定目录，机器绑定与材料身份分开；源日志追加保存，摘要不复制原始流。

## 运行时从哪里开始

按照[启动选择](intake.md)，只有本次明确同意整理后才运行整理工具。接手一个工程，先用契约和工程首页识别资料范围、已有导航和本机资料库绑定。单人执行时经理兼任管理员。持久整理记录放在已有项目索引旁，由索引链接；本机绝对路径沿用本机绑定处，库内资料使用稳定批次和相对位置。按[整理记录工具](../../../tools/catalog.md)登记完整范围并读取模式，向用户显示绑定状态、这次整理模式和涉及的范围。

- **首次全量。** 对照任务目录、实际文档与独立索引，逐项或按批次覆盖约定的工程文档、测试与运行资料、场景及外部库内本项目的归档。已有导航不等于盘点清单，大型数据以批次清单核对位置与身份，结论需要时才读取原件。记录保护区、可再生数据的边界与排除依据。归属或定位不清的项登记缺口。
- **断点接续。** 每完成一个范围就保存盘点证据和外环到内环的阅读入口。下次恢复已完成的范围；继续未整理的部分及待处理缺口。中断、静默或用户暂缓都不会关闭缺口。
- **按需更新。** 有有效完成记录时，只整理本次任务涉及的阶段、模块、新增资料与变化的链接。每次对照工程身份、整套范围及本机绑定；新增范围或绑定变化时，只补盘受影响部分。分类规则实质变化时复核其覆盖范围。

**空工程先有阅读位置。** 若确认约定的文档区和数据区均为空，说明准备创建的位置和结构，得到用户同意后用[空工程目录入口](../../../tools/catalog_scaffold.py)建立可携带的双环目录。适配工程已有名称；有资料时围绕实际内容设计导航，采用自定义结构时按确认方案建立。目录创建完成只是初始化；有真实阶段、模块、资料和验证结果后再登记或评审。外部库的创建沿用各自授权。

## 阶段和模块的两个阅读入口

按工程已有名称组织大阶段及小阶段。外环让用户看到大阶段目标和进度、小阶段的用法变化、评审方案、验证结果、局限与待决定项；模块另有沿时间或阶段可读的修改摘要，回答改什么、为什么、效果与回归范围。内环保存对应的需求决定、版本、详细实施记录、验证口径、原始证据和恢复信息。阶段和模块用同一修改或批次标识互相定位，先复用已有目录与文档。外环可按需要展示引用内环数据的图表，写明问题、条件、结论和来源；数据在内环或绑定资料库就地保存。其他工程使用自己的阶段与模块命名。

## 缺口怎么结束

先修复能够从现有资料核实的问题。遇到加密、丢失、未挂载等无法自行修补的项，真实登记其定位、已核实事实和影响，随即向用户列明具体项，询问“继续等待资料”还是“就此结束处理”。可以把同批问题合在一次提问中，让用户逐项决定。其余范围继续整理。

后来修复的项附可查证的证据；用户明确决定不再修的项按实际答复及出处单独关闭，保留原件未核验、不可恢复等事实。下次无须重复询问已按决定关闭的同一项。没有答复、只关闭其中一项或无法核对的来源，都不能让其余未完成项消失。只有全范围已盘点、可用入口实际可走通，且每个缺口均已核验修复或有明确结束决定，才报告本轮整理完成。关闭整理事项不会将相关工程能力标记为验证通过。

## 让读者找到当前有效的文档

首次产生文档时就将其挂入双环导航。范围内主动找出未挂接的方案、失效链接、指向旧版的当前入口和重复索引。

按读者要解决的问题组织已有导航，例如“了解方案”“安装使用”“查看实施和证据”。读标题与内容、版本及已有决定再确定归属；把用户方案放在任务首选入口，技术资料在需要时可继续追溯。复用已有栏目，在文档之间标明可证实的替代关系。能在授权范围内核实的分类、链接、阅读顺序直接修好，并从首页实际走到当前文件；仅有线索时标明待核，不凭日期判定作废。

管理员可针对实际阅读困难调整已有标题、重写难读段落、拆分或合并说明、新增缺少的概览，也可调整文件位置。先给用户一小批具体提案，列出现有位置或标题、改成什么、解决哪个查找问题、涉及哪些引用以及恢复办法；确认后实施，已有明确覆盖该批的同意直接采用。不要把笼统“整理”当成对任意编辑的批准。实施后核对相对链接和标题锚点，保留历史出处、原始数据和未提交改动。单纯补上已核实的断链或已约定的索引项，可以沿用日常导航整理的授权。

## 资料保留与恢复

| 类别 | 保留与退出依据 |
| --- | --- |
| 核心资产：源码、有效配置、必要输入和恢复说明 | 随受支持版本保留，迁移携带真实依赖 |
| 关键证据：报告及必要失败/复现材料 | 摘要长期保留；原始材料保留最小完整集合，未决失败/争议不因后来通过而删除 |
| 可重建数据：构建/缓存等 | 实际重建方法可用、无唯一修改/活动占用/恢复依赖才列候选 |
| 过程资料：临时记录/备份等 | 收尾核替代结果和恢复点，必要部分转关键证据，其余按批准条件审查 |
| 来源/唯一性未知 | 原位保护，不猜测可删除 |

首次生成/使用时登记所属任务/项目/批次、输入版本及差异、路径基准、状态、保留理由/退出条件、迁移范围和复查点。任务/问题报告复用为索引，大型原始资料只引用；外部项目不混入承载工程验收，忽略文件不等于可删除。

归档/处置前列精确文件清单、真实路径/符号链接、类别/大小、保留条件、活动与其他受支持工作区依赖、唯一性、恢复和不可恢复损失。持续授权须具体到目录、类别、条件和动作，未覆盖项另确认。到期只复查；源变化、目标冲突、身份/校验不符或唯一性未知时保留并停止相关动作。

归档先复制到唯一批次，核对内容/身份、可读性和索引；归档不自动授权删除原件。获准移除时再次核对源未变化，记录实际目标和结果；失败保留原件与中间状态。迁移记旧标识到新位置，不批改原始证据内部历史路径。清单工具不替代来源/唯一性人工判断。

收尾沿工程入口→任务→证据/绑定检查新增/修改/忽略产物、恢复材料及保留边界；修导航不等于原件完整。需要场景复现时沿消费者真实加载格式保存和实测，不制造占位格式冒充可用。

需要精确清单及可恢复归档/隔离时读[资料工具说明](../../../tools/lifecycle.md)，再使用[包内工具](../../../tools/lifecycle.py)。其 cleanup 只列候选、quarantine 是可恢复移动，不是永久删除；工具不自动判断跨工作区依赖或用户批准真伪。

## 已有资料的实体整理

用户选择整理后，管理员用完整的已确认范围和绑定调用 begin，为文档范围传 --layout-scope，再调用 inspect 读取实盘文件。已有盘点仍可沿用，实体布局未验的部分先补整理。管理员自主阅读全文、按本工程语义分类，准备移动映射与面向用户的完整概览，列出首页、契约和忽略区里的适用引用。外环阶段和模块分别直达其内环正文。原始日志、录包和外部归档就地定位。按已批准批次连续执行；拟调整范围有变化时按工程约定确认。

按[工具格式](../../../tools/catalog.md)先预览，再实际调用 arrange --apply。正式文档写入、引用更新与恢复包由该入口执行。逐页核实阅读路径和证据后 review，再运行同一批次检查幂等。跳过整理时不启动这些命令。
