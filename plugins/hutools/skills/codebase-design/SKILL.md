# codebase-design

先读[共同规则](../hutools/references/rules.md)。查看当前模块及真实调用者，沿项目领域术语描述设计。

对外设计沿[用户设计方案](../hutools/references/development.md#用户设计方案)交付。把下面的架构取舍写进技术记录；影响实际用法或部署的取舍，用一个使用实例带回用户方案。

每批回答四点：行为/状态属于谁；谁通过什么接口依赖谁；源码、构建、安装、运行依赖怎样变化；旧部署组合如何验证和恢复。

优先小而清楚的接口、内聚的实现，隐藏内部表示。无持续状态的操作可用函数，共同维护状态/资源/约束时用类。不要为了“深模块”合并无关职责，也不为了可能复用添加抽象。

测试从用户可见行为和实际接口切入；依赖可注入且副作用入口清楚。适配层承担环境转换，核心算法/安全语义留在正确职责内。

说明新增抽象的具体收益及为何现有能力不够；一个合理方案不强制做三份。历史整改单列范围，不自动删除旧测试。设计写清修改批次和旧新部署组合，批准后沿[研发流程](../hutools/references/development.md)实施，实际验证不以方案描述代替。
