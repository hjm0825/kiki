# tdd

每次启用本技能时，主代理立即向用户报告技能全名和用途；子代理立即报给经理，由经理转达。

先读[共同规则](../hutools/references/rules.md)。先将已确认需求变成成功实例与必要反例，预期值来自需求、独立算例或可信基准，不照抄实现。

围绕真实行为和稳定接口安排测试，避免仅检查内部调用或给常量对常量断言。开发按纵向功能执行红 → 绿 → 重构：先运行测试确认失败来自缺失行为/原缺陷并留证；最小实现后回归，必要重构后复测。测试角色独立核验最终集成和端到端，不只认可开发者 PASS。

测试范围在批准批次内选择，不逐个测试点重新问用户。缺陷优先复现，旧代码先保住行为；配置用真实检查，纯文档检查事实/引用。没有合适测试入口时把能力缺口写清，不能发明外围补偿制造通过。

有实际硬性需求才设置硬门；轻微性能波动按观察项和预算处理。只在已批准批次内新增/修改测试和产品源码。测试先行不授权改变接口/规则/预期；判据有问题先说明依据与影响，再按批准范围修订，保留原失败。
