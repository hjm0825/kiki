## 使用方式与责任

用户审一次精确路径和候选差异；模型负责提案，不重抄长补丁。执行请求只引用已审批次、阶段及补丁摘要。**宿主**在独立的写前检查点读取用户维护的策略和只读的已审载荷，核验根、有效期、操作类别、每个目标及其前像，确认该摘要属于本批。校验通过才把原始字节交给已有原生补丁执行器。路径、命令、工具名、任意代码都不是调用者可另传的参数。摘要是内容身份，不是授权。

| 输入 / 输出 | 含义 |
|---|---|
| batch、part、patch_sha256 | 引用受保护清单中的一份载荷；没有清单、身份不符或宿主无法独立核验则不提交。清单只能进一步缩小原策略，不能增广权限。 |
| preimage / expected_after | 每个目标的已有字节摘要或“不存在”。创建、修改、删除分别核对，不能把“可写”解释成“可删”。 |
| receipt | 分开记录未提交、钩子拒绝、执行失败、结果匹配。以实际宿主事件及独立读回为据，不用聊天输出代收据。 |

执行端不得将请求降级成 shell、通用 JS、裸文件 API，或在插件内调用一次保护函数后直接写盘。写前检查至实际修改之间须防止目标被另一写入者更换；若无法保证，拒绝。多文件操作不假定原子，部分完成须保留已发生差异并停止，不自动重放、回退、删除或续期。新调用若需要现有策略以外的能力，不能使用本批授权。

## 实测和剩余条件

- **策略层（只读）**：使用与本机安装件指纹匹配的原处理器、实际批次策略及 A1/A2/B 原生补丁文本调用其判定函数，三个均通过路径规则；四个对照（非清单文件、删除根规则、通用调用、非补丁文件操作）均拒绝。没有向宿主提交调用，没有生成第二套批准策略。
- **内容和顺序（内存）**：从恢复清单对应的十个活动前像、已审 v3 候选和已审导航 diff 独立推导两份更新补丁，与已准备载荷一致；九个期望结果与前次隔离预演逐字节匹配。模拟四种 B 前置状态：原态拒绝、部分 A 完成拒绝、九项精确匹配允许进入 B 核验、其中一项漂移拒绝。阶段顺序是新接口拟施加的附加约束，不是现有 guard 自带承诺。
- **宿主交付尚未验证**：本机 0.155.1 导出的公开协议中有服务端发出的文件变更审批回调，未找到等价的客户端原生补丁提交请求。官方 [File change approvals](https://learn.chatgpt.com/docs/app-server#file-change-approvals) 也说明由服务端先发起变更审批。不能反向使用审批回调当提交接口；其他文件 RPC 不被本批批准。历史原生探针只证明当时的路径，不能充当此接口的联机通过。
- **最小接入范围**：优先复用能暴露受控原生补丁的宿主版本；若通过宿主扩展实现，扩展必须位于受信任的宿主调度层，仍由相同写前检查和沙箱控制真实副作用。当前 HuTools 仓只实现技能、生成器与检查器，单改 guard 或新增一个可调用脚本不能提供该能力。未经另行确认不修改宿主、不安装服务、不使用正式文件试验。
- **接入验收**：先用可丢弃的、经独立确认的样例，走准备正式使用的相同调度入口：成功一次、越权拒绝一次、过期或前像变化拒绝一次，外部读回；随后验证 A 未完整时 B 不产生执行事件。缺少宿主收据或事件时记未验证。未达到此门槛不请求重新签发正式许可。
