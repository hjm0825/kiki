# 文档管理员如何整理项目

每次在工程里输入“运行”，管理员会显示项目和本机资料库位置，并问你“本次整理文档和数据，还是跳过直接做任务？”你可以只确认位置，也可以指定这次跳过；下次运行再选择。同一次接手已经确认过的位置会明确显示。选整理时，首次全量盘点，以后按任务更新。空工程可以先商定并建立外环、内环和数据目录。已有资料从两个方向查看：

| 打开哪里 | 你看到什么 | 继续查到哪里 |
| --- | --- | --- |
| 大阶段 → 小阶段 | 功能目标、使用变化、完成情况和仍需要决定的事 | 该阶段的方案、验证口径、失败和原始数据 |
| 模块 → 修改记录 | 这次为何改、改了什么、验证解决了什么问题 | 同一修改所属阶段、版本和详细证据 |

例如从优化阶段进入 R1 看规划效果，或从规划模块查看历次修改，两条路径指向相同的决定和验证。外环可以用来自内环的图表解释变化；原始数据沿内环索引定位，已归档的资料继续使用本地资料库。阶段名称沿用各工程的习惯。

管理员发现旧标题看不出用途、方案与验证混在一起，或项目缺少一页总览时，会告诉你打算改哪些标题、增补什么、哪些链接要随之调整。你确认这批建议后，它会修改内容、整理位置并验证新入口。

选择整理后会显示“断点接续”或“按需更新”。若资料加密，管理员告诉你具体资料及影响。你可以等待可读原件，也可以明确表示“这份不再修”。选择后者，这项计作整理完成，仍写明原件未核验。其他缺口独立处理，全部范围和缺口都处理完，才会显示本轮完成。

## 在 0.2.0-rc.5 上如何验收

| 场景 | 2026-11-18 实际观察 |
| --- | --- |
| 只确认路径，随后选择跳过 | 经理单独等待整理选择；跳过前后，隔离项目的 6 个文件和整理记录逐字节一致。 |
| 首次全量与后续编辑 | 试用项目从外环 R → R1 及模块两个入口查到同一车序结果，内环三笔订单、两笔已分配、一笔等待的数据与外环表格一致。经理针对旧标题与正文提出一批具体建议，待用户确认后才实施；再运行仅复核受影响范围。 |
| 加密、等待与结束修复 | 一个不可读取的清单与一个加密回放分别登记。只同意结束回放时，全局仍显示未完成；补充清单材料并核验后才进入按需模式。内环保留未重放和恢复材料的局限。 |
| 工程为空 | 实际运行安装版生成一个总入口、五个分区说明，每个入口均可达。没有虚构业务阶段，也没有产生全量已完成标记。 |
| 复发与重新绑定 | 旧来源缺口和新来源缺口各自保留，只关闭旧来源时新来源仍待办。实际修复的原件再次缺失时会重新进入待办，之前的核实记录可查。 |

完整回归运行 91 项，包含 12 项新增的整理及初始化测试，另通过分发检查与技能入口校验。首次开发测试在工具尚未存在时出现红态；独立复核另外发现并修复了改绑和缺口复发可能误报完成的两处问题。一次沙箱中的测试因临时夹具权限受阻，在可写临时目录按原用例重跑通过。安装件由正式安装命令生成，37 个分发文件分别与源码核对一致。这里的交互证据来自独立会话实例直接读取安装态技能，CLI 验证使用安装态工具。

## 实体目录整理

选择整理后，管理员按已批准的范围为现有工程生成阶段和模块的实体目录、面向用户的概览与技术正文，调用整理器执行文档迁移、引用改写和复核。上一轮只完成盘点的工程继续补整理，重复调用复用已归位文件。
