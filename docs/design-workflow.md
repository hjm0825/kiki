# 用户怎样与 HuTools 一起设计

你提出一个想法时，经理先讨论实际用法。例如要让规划算法能在其他平台上工作，先弄清新平台提供什么数据、算法返回什么结果。工程师可以调查现有实现，影响选择的技术约束由经理说清楚。你已经指定函数并提出具体问题时，直接得到技术回答。

每个设计任务都有一份可以独立评审的方案。打开工程导航，沿任务名称就能看到实际使用过程、设计取舍和仍需要你决定的事项。讨论有进展就更新原方案。任务停在设计阶段时，这份文档就是交付物；需要实施时可以继续查看关联的开发记录。

资料管理员在任务接手、产生文档和阶段收尾时主动核对相关目录。散落但身份清楚的方案会挂回导航，旧版会注明后继入口，用户说明、部署操作和技术证据按用途找到。归属有疑问的材料标为待核，大规模搬移前先核对引用和恢复办法。

## 验证范围

2026-11-18 对源码候选 0.2.0-rc.4 做了三次独立试用。以下是当次观察，可用同类输入复查。

| 给工具的任务 | 实际结果 |
| --- | --- |
| 规划器目前依赖 ROS，希望将来适配其他平台，先讨论 | 首轮用一单运输任务询问规划器负责算路线还是也负责派车，再问新平台打算怎样调用。首轮没有要求选择代码改动。 |
| 已知两点为 (0,0) 和 (3,4)，只问距离表达式的含义 | 直接解释直线距离并算出 5。 |
| 一个有旧方案和断链的调度项目，输入和预期结果已给定，先做方案 | 更新现有用户方案，用订单和车辆的例子讲清结果，单列待审阅内容。首页将当前方案列首，修正操作说明断链，保留旧版与待核笔记。从首页遍历 6 份文档、9 个链接均可达。 |

分发包检查、四个涉及的技能入口校验及原有 79 项回归通过。首次沙箱回归中 64 项因临时文件写入权限出错；经宿主许可按原命令重跑，79 项全部通过。样例检验的是这些任务中的可观察结果，不能代表所有设计或所有文档库。

独立评审发现首次纯咨询可能先被询问资料库、单独质询入口可能漏交设计方案。修订后复核两项关闭，最终源码重新通过上述回归。

本机 Codex 安装入口返回 0.2.0-rc.4，插件列表显示已启用，安装件与源码的 34 个分发文件逐文件一致。行为试用针对源码；后续全新客户端会话中的使用体验需另行观察。
