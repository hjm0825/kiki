### 四项观察

- **质量**。相对路径对照中，同一个检查命令已经执行，旧版登记数仍为零。资料恢复红态则读回第一项已经移动并发现过时的回执。独立审查随后发现接近 5 MiB 的旧回执可能在恢复中途超出可读上限。每个问题各自计入发现与复核。
- **用户负担**。用户通过一次卡片批准这一批的修改范围。Git 试行中，候选提交范围和 dirty 疑点都由测试角色和经理根据对象证据解决，用户救场、重复解释和重复取证次数均为零。宿主的沙箱审批属于另一类交互。
- **历时**。Git 试行从创建样例到核对最终提交树共 73.568 秒。开发与审查有并行时段，工作片段分别保存；包括模型耗时在内的纯等待和净执行时间无法完全拆分。
- **协作成本**。两项源码改动有不同的文件所有者，最终审查独立。Git 样例经历一次真实暂停和一次经理解除疑点。实际片段和原始回执支持阶段复核，目前没有可比较的旧流程基准或完整 token 统计。

[试行数据](../validation/b03/trials.json)保留了命令结果、时间戳、提交与内容摘要。观察员结束职责后，正式工程仍显示执行策略未绑定，经理继续只读核查和获批的隔离验收，涉及长期绑定或真实数据处置的操作没有启动。观察员意外断网及跨机器恢复缺少现场记录。

## 最终版本、独立审查与安装

验收对象为 `0.2.0-rc.3`。正式工作区完整回归 **79/79 通过**，原始命令输出由[本批任务状态](../validation/b03/task.json)登记。

| 改动 | 修复前与最终验证 |
| --- | --- |
| 工作流 | 基线用相对路径运行了命令却未登记证据；过时报告仍显示完成，CLI 缺少结果字段。3 项红态修复后，26 项工作流测试通过。实际安装件另行从消费者目录用相对参数执行一次指令，读回一个计数和一条日志。随后改变输入，状态及报告同为 `needs_revalidation`，Stop 对运行中、完成、输入过期依次阻止、放行、阻止。 |
| 资料恢复 | 普通文件占用后一个目标的祖先时，预检在移动前报告冲突。中断后保存各次尝试及原因。独立审查发现补记历史可能超过主回执的读取上限；新增临界回归及连续多次失败试行，22 项资料测试通过。安装态 CLI 对冲突批次实测移动 0 项，用户文件原样保留；解除冲突后移回 2 项，再次恢复 0 项。 |
| 独立复核 | `host_review` 在全量整合前发现回执容量问题并退回。修复后独立构造 5,242,879 字节的旧 v1 回执，两次中断，成功从主回执追到两段分别为 5,243,199 和 5,243,414 字节的详情。两段历史字节和已移动路径保留；余下 1 项恢复，重试移动 0 项。复核还覆盖相对路径、有效状态、旧工作片段及九项技能导航，无剩余交付阻塞。 |

在私有安装目录上依次执行 Codex CLI 0.155.1 的 `plugin marketplace add` 和 `plugin add hutools@hutools`，后者返回 `version=0.2.0-rc.3`。排除 Python 缓存后安装件的 34 个文件与源码逐字节一致。按路径排序的文件摘要映射经 Python `json.dumps(mapping, sort_keys=True)` 序列化后的 SHA-256 为 `b987a70f27d65525762f7f5f20ed8bf9283f3e78ff76537955e411cdcea0a74c`。全新配置的 `hooks/list` 显示三个事件均启用，信任状态均为 `untrusted`，符合首次人工审阅流程。

在空样例、只读沙箱的新线程中选择已安装的 HuTools 入口，用户文本仅为“运行”。实际模型在支持处理中提问的规划模式下发出一次含两个问题的原生 `item/tool/requestUserInput`，分别提供开发功能、分析问题、其他咨询，以及资料库选项。测试端通过协议选择“其他咨询”和“暂未建立”，收到第二张卡片后以自由文本询问资料库用途。助手直接用中文解释并保留“待建立”状态，回合正常完成。此项验证模型、卡片协议与接续；当前交付对话也通过卡片实际收到用户的批次决定。

首次入口试验的默认模型被账号拒绝。切换到可用模型后在普通模式观察到菜单文字，未取得卡片答复；规划模式成功收发原生卡片。测试驱动首轮误选了“已有其他位置”，修正匹配后以实际选项完成上述验证。安装测试最初使用系统临时目录时复制失败，正式工作区的一次性子目录成功。所有结论按最终实测的环境和调用方式解释。
